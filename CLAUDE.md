# PrevizXR: notes for Claude and contributors

Open-source VR previsualization web app. Block out scenes in VR (actors, props, virtual camera), record camera takes, and export frame-synced video passes (clay, color_id, depth, normals, OpenPose) as input for generative AI video models.

## Stack

- Video: WebCodecs + Mediabunny (MP4 muxing); fflate for zips. `mp4-muxer` is deprecated in favor of Mediabunny, so don't add it.
- TypeScript (pinned to ~6.0 because typescript-eslint doesn't support TS 7 yet), Vite 8, Three.js r186, Vitest 5, ESLint 10 flat config.
- WebXR via Three.js (`renderer.xr`, XRControllerModelFactory, XRHandModelFactory). Sessions are immersive-vr or immersive-ar (passthrough, "XR" in the UI); `XRSessionManager.mode` says which, and `App.tick` hides the floor in the headset view during AR.
- No backend. Static site deployed to GitHub Pages at `/PrevizXR/` (see `base` in `vite.config.ts`).
- Targets: Meta Quest 3 browser (immersive-vr) and desktop Chrome/Edge (orbit and keyboard). The Immersive Web Emulator extension works because it polyfills `navigator.xr`.

## Architecture

**Capture and render are separate.**

1. **Capture** (VR or desktop) records a *take*: JSON with fps, duration and per-frame camera transform and lens data, every object's transform, and actor clip names and playback times.
2. **Render** (desktop recommended) loads scene and take, replays deterministically frame by frame at a fixed fps (never a wall clock), renders each pass to an offscreen target, and encodes.

**Single source of truth:** `src/model/` holds the serializable scene model, which is plain JSON-safe objects with no Three.js types. The Three.js scene graph is derived from it by a sync layer. Never store state only on a `Object3D`; mutate the model through the `Editor` (which records undo/redo) and let `SceneSync` update Three.js.

Interactive frame loop: `App.tick` → desktop controls → `onFrame` callbacks → render. Objects tagged `userData.helper = true` (grid, gizmos, UI) are excluded from export passes.

### Key flows

- **Edits:** UI → `Editor` method → `'doc'` event → `SceneSync.reconcile()` updates Three.js, and `Project` schedules an autosave. Drags call `editor.begin()`, then `setTransform(..., transient=true)` each frame, then `commit()`, which records one undo step.
- **Assets:** an `AssetRef` in the model (`primitive` | `bundled` | `poly` | `light`). `AssetLoader` caches each GLB once and returns skinned-safe clones wrapped in a normalizing group (base at y=0, centred, scaled to the asset's `Fit`). `poly` refs carry title/creator/licence/fit so scene files are self-describing.
- **Reference images:** `AssetRef { source: 'image', id, aspect }`; `id` is a content hash in the image library (IndexedDB), never inside the SceneDoc. Exported scene files add an `embeddedImages` map (id → data URL) that `Project.importFile` restores. `SceneObject.hiddenInRenders` (any object; default for images) puts the root in `SceneSync.renderHidden`, which `App.renderClean/withEditorHidden` hide, so it never reaches the monitor or passes.
- **Camera:** `SceneDoc.camera` (transform + lens) is selectable under `CAMERA_ID` like an object: `Editor.setTransform(CAMERA_ID, …)` moves it (scale is always 1), and `Editor.updateLens()` changes the lens. `VirtualCamera` keeps a `PerspectiveCamera` in sync (vertical FOV from `lens.ts`) and registers its root with `SceneSync.registerRoot`, so picking, gizmos and VR grabbing work unchanged. It is not in `SceneSync.root`, so it never appears in passes.
- **Clean renders:** `App.renderClean(camera, target?)` hides everything registered with `App.addEditorOnly()` (grid, labels, paths, gizmo, controllers, reticles, camera body, light bulbs) and renders. With a target it is safe inside an XR frame. The camera monitor uses it now; export passes will too. Register any new editor-only object.
- **Paths:** actors keep waypoints in `actor`; props and lights in the optional `motion` (same `MotionPath` shape). Read with `pathOf(obj)`, mutate with `editPath(obj)` inside an edit; add/remove points with `addWaypoint/popWaypoint/clearWaypoints` (they keep `handles` aligned). All paths are cubic Béziers (model/bezier.ts): `MotionPath.handles[i]` (aligned with [start, ...waypoints]) and `CameraKey.handles` are offsets; missing = auto (Catmull-Rom tangents, so unedited camera paths match the old spline). Objects travel at constant speed by arc length; camera time is linear per segment. Drag points through `movePathPoint` (mirrors the partner handle; actors stay at y = 0) from `PathHandles` (VR grab, desktop gizmo). Camera keys go through `Editor.addCameraKey/editKeys/goToKey`; `KeyframePath` updates its markers in place so VR can drag one (`XREditor` writes the key with `editor.transient`).
- **Preview:** `Playback` drives objects; `Studio` also poses the camera from `sampleKeyframes` (via `VirtualCamera.setOverride(sample, autofocus)`) while previewing with 2+ keys and no take busy. In VR the monitor can be detached (`VirtualCamera.detachMonitor/attachMonitor`, view-only, not in the scene) and grabbed.
- **Time:** `objectPoseAt(obj, t)` (model/motion.ts) is the single definition of where an object is at scene time t. `SceneSync.setPreviewTime(t)` uses it for the preview; `null` returns to live editing.
- **Takes:** frame k is at exactly k / fps. While recording, `TakeRecorder.push(t, camera)` interpolates the live camera (sampled at display rate) to frame times, and objects come from `objectsAt(docSnapshot, k / fps)`. Playback uses `sampleTake(take, t)`, which returns frame k exactly at t = k / fps and interpolates between frames. It applies `SceneSync.setTakePoses()` and `VirtualCamera.setOverride()`, neither of which touches the model. Smoothing is a per-take setting applied by `cameraFrames()`; raw frames are never modified. Rendering iterates frames 0…frameCount−1 with `sampleTake(take, k / fps)`.
- **Rendering:** `TakeRenderer.render()` pauses the interactive loop (`App.pause/resume`), waits for every model (`SceneSync.whenLoaded`), and for each frame poses objects (`setTakePoses`) and a dedicated PerspectiveCamera (FOV from the take's sensor/aspect and the frame's focal length). It then renders each pass into an offscreen target under `App.withEditorHidden`. Pass outputs go into 8-bit linear targets, so bytes are exact: color_id sets material colors without sRGB conversion, and depth writes (far−z)/(far−near). Clay renders HDR with MSAA, then `OutputPass` tone-maps and sRGB-encodes it. Pixels are read back synchronously (the async readback polls with setTimeout, which background tabs throttle), flipped, and fed to a `FrameSink`. Avoid any browser API that background tabs throttle (canvas toBlob/convertToBlob, timers, rAF) in this loop. New passes plug into `Passes.run()` and `PASSES`/`PASS_INFO` in plan.ts, plus their encoding entry in manifest.ts. The pose pass is drawn in 2D (OffscreenCanvas + getImageData, which background tabs don't throttle) from `PoseExtractor`. Bone names are matched after normalizing (`JOINT_BONES`); add candidates there for new rigs. Each render returns one zip (`<scene>_<take>_previz/…`, fixed timestamps so identical renders produce identical bytes) plus individually downloadable MP4s and camera files.

## Conventions

- Pure logic (math, model, serialization, playback timing) lives outside Three.js-dependent files where possible and gets a `*.test.ts` next to it.
- Units: metres, seconds, millimetres for focal length and sensor sizes. Rotations in the model are quaternions `[x, y, z, w]`.
- File formats carry `format` and `version` fields; bump the version and add a migration when the shape changes.
- VR input: controllers and tracked hands. Hands use the input source's select events (pinch) via `XREditor.updateTrackedHand`. `prefs.leftHanded` swaps the pointer and menu hands, so never hard-code 'left'/'right'; use `dominantHand()` / `isOffHand()`. Per-device preferences live in `app/prefs.ts` (localStorage), never in scene files.
- Performance: in VR, `Studio` steps `VirtualCamera.setMonitorQuality()` by measured FPS (MONITOR_LEVELS). Keep per-frame work off the hot path (no allocations, throttle precise bounds and raycasts against skinned meshes).
- UI: styles are tokens + components in styles.css (no framework). Prefer icon buttons with `title` and `aria-label`, and toggle buttons with `aria-pressed`. Keep the top bar for scene-wide actions, the right panel for properties of what's selected, and the viewport toolbar for view/gizmo tools.
- Accessibility: new UI must be keyboard reachable with visible focus; announce state changes that happen away from focus with `ui/announce.ts`; toggle groups use `aria-pressed`, tabs follow the WAI-ARIA pattern (see AddPanel).
- Keyboard shortcuts are ignored while focus is in an input. WASD navigation only listens on the focused canvas.
- Editor-only objects (labels, gizmos, paths, menu, light bulbs) set `userData.helper = true` so export passes can skip them.
- Assets must be CC0 or CC-BY, listed in `ASSETS.md`, with a `credit` in `src/assets/catalog.ts`. Library (Poly) models are never committed; they load from static.poly.pizza (CORS-enabled). Mesh2Motion assets load from jsDelivr at the pinned `M2M_COMMIT`.
- **Clips:** `ActorSettings.clip` is a basic clip (`ACTOR_CLIPS`: idle/walk/run/sit) or a library clip name. Bundled actors and animated Poly models (`AssetRef.clips`) play every clip by name and find basic clips with `basicClipRoles`; Mesh2Motion characters (`AssetRef` source `m2m`) get every clip by name plus `roles` mapping the basic ones (`LoadedAsset.roles`). Extra animation files load on first use (`SceneSync.requestClip`, tracked in `loading`; `TakeRenderer` calls `prepareClips` first). Library clips go through `fitClips` (Mesh2Motion's `clean_track_data`: rotations + the family's `trackingBone` position only, scaled by `pelvisScale`), so they fit each model's proportions. `isTravelClip` drives idle-on-arrival, `clipSpeed` suggests path speeds, `isOneShotClip` sets LoopOnce + clamp.
- Keep Quest performance in mind: target 72 fps, avoid per-frame allocations in hot paths, and reuse vectors.

## Commands

```bash
npm install
npm run dev        # http://localhost:5173 (also exposed on the LAN)
npm run check      # lint + typecheck + tests
npm run build      # production build into dist/ with base /PrevizXR/
npm run preview    # serve dist/
npm run catalog    # refresh public/catalog/poly-google.json from poly.pizza
```

Testing on a Quest during development: WebXR needs a secure context. Either use `adb reverse tcp:5173 tcp:5173` and open `http://localhost:5173` in the Quest browser, or push to `main` and use the Pages URL.

## Deploy

`.github/workflows/deploy.yml` runs lint, typecheck, tests and build on every push and PR, and deploys `dist/` to GitHub Pages on pushes to `main`. Pages source must be set to "GitHub Actions".

The `window.previz` global exposes the `Studio` (with `.app`, `.editor`, `.sync`, …) for debugging.
