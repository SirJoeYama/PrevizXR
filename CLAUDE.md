# PrevizXR: notes for Claude and contributors

Open-source VR previsualization web app. Block out scenes in VR (actors, props, virtual camera), record camera takes, and export frame-synced video passes (clay, color_id, depth, normals, OpenPose) as input for generative AI video models.

## Stack

- TypeScript (pinned to ~6.0 because typescript-eslint doesn't support TS 7 yet), Vite 8, Three.js r186, Vitest 5, ESLint 10 flat config.
- WebXR via Three.js (`renderer.xr`, XRControllerModelFactory, XRHandModelFactory).
- No backend. Static site deployed to GitHub Pages at `/PrevizXR/` (see `base` in `vite.config.ts`).
- Targets: Meta Quest 3 browser (immersive-vr) and desktop Chrome/Edge (orbit and keyboard). The Immersive Web Emulator extension works because it polyfills `navigator.xr`.

## Architecture

**Capture and render are separate.**

1. **Capture** (VR or desktop) records a *take*: JSON with fps, duration and per-frame camera transform and lens data, every object's transform, and actor clip names and playback times.
2. **Render** (desktop recommended) loads scene and take, replays deterministically frame by frame at a fixed fps (never a wall clock), renders each pass to an offscreen target, and encodes.

**Single source of truth:** `src/model/` holds the serializable scene model, which is plain JSON-safe objects with no Three.js types. The Three.js scene graph is derived from it by a sync layer. Never store state only on a `Object3D`; mutate the model through the `Editor` (which records undo/redo) and let `SceneSync` update Three.js.

Interactive frame loop: `App.tick` → desktop controls → `onFrame` callbacks → render. Objects tagged `userData.helper = true` (grid, gizmos, UI) are excluded from export passes.

### Key flows

- **Edits:** UI → `Editor` method → `'doc'` event → `SceneSync.reconcile()` updates Three.js, and `Project` schedules an autosave. Drags call `editor.begin()`, then `setTransform(..., transient=true)` each frame, then `commit()`, which records one undo step.
- **Assets:** an `AssetRef` in the model (`primitive` | `bundled` | `poly` | `light`). `AssetLoader` caches each GLB once and returns skinned-safe clones wrapped in a normalizing group (base at y=0, centred, scaled to the asset's `Fit`). `poly` refs carry title/creator/licence/fit so scene files are self-describing.
- **Camera:** `SceneDoc.camera` (transform + lens) is selectable under `CAMERA_ID` like an object: `Editor.setTransform(CAMERA_ID, …)` moves it (scale is always 1), and `Editor.updateLens()` changes the lens. `VirtualCamera` keeps a `PerspectiveCamera` in sync (vertical FOV from `lens.ts`) and registers its root with `SceneSync.registerRoot`, so picking, gizmos and VR grabbing work unchanged. It is not in `SceneSync.root`, so it never appears in passes.
- **Clean renders:** `App.renderClean(camera, target?)` hides everything registered with `App.addEditorOnly()` (grid, labels, paths, gizmo, controllers, reticles, camera body, light bulbs) and renders. With a target it is safe inside an XR frame. The camera monitor uses it now; export passes will too. Register any new editor-only object.
- **Time:** `objectPoseAt(obj, t)` (model/motion.ts) is the single definition of where an object is at scene time t. `SceneSync.setPreviewTime(t)` uses it for the preview; `null` returns to live editing.
- **Takes:** frame k is at exactly k / fps. While recording, `TakeRecorder.push(t, camera)` interpolates the live camera (sampled at display rate) to frame times, and objects come from `objectsAt(docSnapshot, k / fps)`. Playback uses `sampleTake(take, t)`, which returns frame k exactly at t = k / fps and interpolates between frames. It applies `SceneSync.setTakePoses()` and `VirtualCamera.setOverride()`, neither of which touches the model. Smoothing is a per-take setting applied by `cameraFrames()`; raw frames are never modified. Rendering (milestone 5) must iterate frames 0…frameCount−1 and use `sampleTake(take, k / fps)`.

## Conventions

- Pure logic (math, model, serialization, playback timing) lives outside Three.js-dependent files where possible and gets a `*.test.ts` next to it.
- Units: metres, seconds, millimetres for focal length and sensor sizes. Rotations in the model are quaternions `[x, y, z, w]`.
- File formats carry `format` and `version` fields; bump the version and add a migration when the shape changes.
- Controllers are the primary VR input. Hand tracking is rendered but not interactive yet (planned for milestone 7).
- Keyboard shortcuts are ignored while focus is in an input. WASD navigation only listens on the focused canvas.
- Editor-only objects (labels, gizmos, paths, menu, light bulbs) set `userData.helper = true` so export passes can skip them.
- Assets must be CC0 or CC-BY, listed in `ASSETS.md`, with a `credit` in `src/assets/catalog.ts`. Library (Poly) models are never committed; they load from static.poly.pizza (CORS-enabled).
- Keep Quest performance in mind: target 72 fps, avoid per-frame allocations in hot paths, and reuse vectors.

## Commands

```bash
npm install
npm run dev        # http://localhost:5173 (also exposed on the LAN)
npm run check      # lint + typecheck + tests
npm run build      # production build into dist/ with base /PrevizXR/
npm run preview    # serve dist/
npm run catalog    # refresh public/catalog/poly-google.json from poly.pizza
```

Testing on a Quest during development: WebXR needs a secure context. Either use `adb reverse tcp:5173 tcp:5173` and open `http://localhost:5173` in the Quest browser, or push to `main` and use the Pages URL.

## Deploy

`.github/workflows/deploy.yml` runs lint, typecheck, tests and build on every push and PR, and deploys `dist/` to GitHub Pages on pushes to `main`. Pages source must be set to "GitHub Actions".

The `window.previz` global exposes the `Studio` (with `.app`, `.editor`, `.sync`, …) for debugging.
